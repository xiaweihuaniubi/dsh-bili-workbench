# dsh-bili-workbench 项目功能说明

文档日期：2026-10-27。对应本次整理的 1.3.0 待发布功能，不代表该版本已经在 GitHub 发布。

## 一、项目简介

`dsh-bili-workbench` 是运行在 DSH（DeepSeek Harness）web 界面中的 B站创作插件，把视频发现、素材采集、创作方案、视频渲染、审核投稿和账号互动放进同一个工作台。

它主要帮助使用者把“刷到有意思的视频”变成“可查找、可引用的素材”，再结合模型生成创作方案。使用者可以修改方案、渲染预览，并决定是否投稿。

插件采用本地存储，账号操作通过 bili-cli 执行；模型能力来自 DSH 当前模型或使用者配置的独立模型服务。它需要配合 DSH 和外部工具使用，不是独立运行的剪辑软件。

## 二、主要菜单

| 菜单 | 主要用途 |
|---|---|
| 素材库 | 查看采集的视频、字幕、金句、时间点、关键帧和内容判断 |
| 刷B站 | 浏览热门、关键词搜索、查看视频，以及处理消息和互动草稿 |
| 创作中心 | 创建视频需求、选择创作风格、修改方案、管理版本和开始渲染 |
| 成片投稿 | 预览成片、本地审核、检查投稿参数、提交和同步平台状态 |
| 刷B站设置 | 单独管理采集计划、内容偏好、互动权限、模型链和音色 |
| 我的 | 登录账号、查看账号数据、管理素材目录、发布权限和记忆 |

## 三、素材采集与管理

### 1. 视频发现

- 支持热门内容浏览和关键词搜索。
- 支持进入单条视频查看相关信息，并采集到本地素材库。
- 可配置关注关键词，让定时采集围绕感兴趣的内容展开。
- 可手动开始一轮采集，也可根据设定时段和每日上限定时运行。

### 2. 素材整理

根据视频及接口实际提供的内容，保存或整理：

- BV号、标题、UP主、时长、采集时间及可获取的播放、点赞等数据。
- 字幕或逐字稿、可引用金句及对应时间点。
- 关键帧、视频封面、热评、热门弹幕和相关梗。
- 模型对内容的简短判断、可用片段及筛选理由。

视频判断使用“值得看 / 可以看 / 跳过”等档位，帮助后续选材。素材按 BV 标识去重管理，减少重复采集。

素材库提供列表或卡片展示、搜索筛选和详情查看。并非每个视频都有字幕或完整可用信息；缺少的内容不会自动变成可引用的事实。

### 3. 日报

支持整理采集结果并生成日报，可设置日报粒度。日报用于回看和筛选，不会因此自动创建视频或投稿。

## 四、创作中心

### 1. 需求驱动的方案生成

使用者输入主题、想要的节奏、时长或其他要求，选择创作风格后生成方案。

方案通常包含：标题、创作角度、引用素材、分镜、原片时间点、旁白或原声方式、预计时长等。模型依据可用素材编排，实际效果与素材质量、字幕完整性和模型能力有关。

素材不足时，插件会创建长任务，按主题查找和采集素材；条件满足后继续生成方案。任务可以暂停、继续、重试或删除。

**生成方案不会自动开始渲染，也不会自动投稿。**

### 2. 三种创作风格

| 风格 | 表达方式 | 适合内容 |
|---|---|---|
| A · 吐槽整活 | 围绕真实台词和反差设计铺垫、吐槽、包袱及回扣，可组合原声与旁白 | 反差吐槽、趣味主题、素材点评 |
| B · 名场面混剪 | 3秒以内片头、纯原声正文、简短片尾，正文不插入解说 | 名场面接力、完整对话、原声包袱 |
| C · 自定义 | 根据补充要求决定结构和节奏；未补充时按主题编排 | 有明确创作要求的其他内容 |

B 模式至少包含两段不同的真实片段，按完整对话或包袱选择切点，不固定为几秒一切。单段工程上限为180秒，不表示推荐把每段都剪成180秒。

提示词强调自然口语、具体场景和真实反差，减少模板开场、泛泛总结和硬堆流行词。模型不会因为设置了“整活”就必然产出好笑内容，使用者仍需查看方案和成片。

### 3. 版本管理

- v1：第一次生成的方案。
- v2、v3……：主动修改后生成的新版本。
- 版本下拉可以查看历史方案，并返回当前版本。
- 修改风格后需要生成新版本，确认方案后再渲染。
- 同一版重复渲染不会增加方案版本号。

方案卡集中提供渲染、预览、修改、查看分镜、日志和删除入口。删除需要卡片内确认；删除方案及其历史版本时，已有成片独立保留，需到“成片投稿”单独管理。

## 五、视频渲染与成片

### 1. 渲染流程

根据方案需要执行素材检查、真实片段准备、旁白配音、画面渲染、音轨处理、字幕与封面生成。

- 真实原片按经过校验的 BV 和时间点下载、缓存。
- 原声镜头保留原音，不生成覆盖原声的旁白。
- 旁白镜头可使用所选音色生成配音及对应字幕。
- 支持模板画面、原片、标题和封面等组合。
- 默认形象动画缺失时可使用静态形象；显式指定的自定义资源缺失会报错。

### 2. 进度与错误

页面显示渲染进度、失败原因和日志。任务与日志会落盘，方便重启后排查。

素材下载、配音服务、浏览器、FFmpeg 或模型不可用时，可能导致任务失败；不能将“没有报错的方案生成”当成“视频已经渲染成功”。

### 3. 预览

已生成成片可在页面播放，预览支持关闭按钮、Esc和点击背景关闭。旧视频不会因模板或提示词升级自动改变，需要使用者主动改版或重新渲染。

## 六、审核与投稿

### 1. 本地审核

使用者先预览成片，再选择本地审核通过或打回重做。成片可以按全部、待本地审核、待投稿和投稿记录筛选。

本地审核是使用者对成片的确认，不是 B站平台审核。

### 2. 投稿检查与提交

- “投稿检查”用于查看 CLI 投稿参数和预演结果，不等于上传或取得平台通过。
- 实际提交需要开启投稿权限、本地审核通过并进行确认。
- 支持配置默认标签、分区等参数。
- 投稿执行期间阻止重复操作，减少重复提交。

### 3. 状态区分

| 状态 | 含义 |
|---|---|
| 已完成 · 待审 | 本地有成片，等待使用者审核 |
| 本地审核通过 | 本地确认通过，可以检查参数并投稿 |
| 投稿中 | 正在执行上传或提交 |
| 已投稿 · 待平台确认 | 已取得有效 BV，仍需核对平台审核和发布结果 |
| 平台已发布 | 同步平台状态后确认已发布 |
| 平台退回 | 平台返回退回原因，需按原因处理 |
| 投稿结果待确认 | 超时、断连或缺少明确结果，需先核对，避免盲目重投 |

预上传或参数检查阶段被明确拒绝时，会显示“投稿未提交”和原始原因，不当成已经提交，也不误报结果未知。

对于真正未知的结果，支持同步已有 BV，或在人工确认没有产生稿件后解除限制再重试。插件不会自动代替使用者核对或重投。

删除本地成片不会删除 B站上已存在的稿件。平台风控、审核和账号权限仍由 B站决定。

## 七、账号、消息与可选互动

### 1. 账号管理

“我的”提供扫码登录、退出、登录状态查询和可获取的账号统计。查询尚未完成时显示“正在确认登录状态”，与确认未登录区分。

### 2. 消息和互动草稿

支持查看 CLI 能提供的相关消息，生成评论、回复或私信草稿，并查看原文和执行结果。实际可用消息类型与账号权限、接口支持有关。

### 3. 自动互动

按需配置的能力包括：

- 采集视频后自动评论，并按设置提及相关账号。
- 对回复进行自动回复。
- 检查指定主人账号的 @ 任务，如看视频、看评论或总结。
- 在配置允许时使用私信交付较长内容，或监听相关私信。
- 对符合筛选条件的视频自动收藏到指定收藏夹。

这些功能会使用自己的 B站账号执行相应操作，需分别配置。发布版默认关闭自动评论、自动回复、私信监听和投稿权限；不能把“自动采集”和“允许公开发送”理解成同一个开关。

## 八、设置与记忆

### 1. 独立设置菜单

“刷B站设置”集中管理：

- 定时采集开关、时段、每日数量。
- 关键词、表达风格和日报粒度。
- 可选自己的视频合集背景。
- 主人标识、称呼、提及对象及互动频率上限。
- 自动评论、回复、私信等独立权限。
- 模型链和默认音色。

表单使用统一下拉、复选框和单选组，支持键盘选择、选中反馈、焦点与禁用状态。

### 2. 长期记忆

按配置维护主人偏好、工作台事实和经历记录，供后续评论、回复及创作参考。可查看、增加、删除记忆，处理待确认条目，并选择是否开启任务后复盘。

记忆会影响后续生成，不保证每次记忆内容都正确；使用者可以查看并管理它们。

## 九、运行环境与数据

### 1. 依赖

- DSH web 与 Node.js。
- bili-agent/bili-cli：账号和平台操作。
- 模型服务：内容判断、方案和互动草稿。
- yt-dlp：真实片段下载。
- edge-tts：旁白配音。
- FFmpeg/ffprobe：音视频处理和检测。
- Remotion、React、sharp以及Chrome/Edge：模板渲染和图片处理。

具体安装步骤见项目 README 和 GitHub 发布指南。源码和 tgz 都不包含这些工具所需的全部外部环境。

### 2. 数据存放

默认数据目录为用户目录下的 `.dsh-bili-workbench/store`，可在“我的”切换。素材库、方案、任务、成片、日志和记忆主要保存在本地。

“本地保存”不等于“完全离线”：模型调用会发送必要的创作上下文至所用模型服务；采集、配音和账号操作也会访问相关服务。

发布包不附带维护者的登录信息、模型密钥、个人配置、历史素材、成片和运行缓存。安装者需要登录自己的账号并配置自己的环境。

## 十、推荐使用流程

1. 安装插件及必要环境，重启 DSH，进入会话中的 B站工作台。
2. 到“我的”登录自己的 B站账号。
3. 到“刷B站设置”设置关键词、频率、音色和模型；按需决定是否开启互动。
4. 手动采集或浏览素材库，确认已有可用字幕和片段。
5. 到“创作中心”输入需求，选择 A/B/C，生成方案。
6. 查看分镜和素材引用，有问题则生成新版本。
7. 手动开始渲染，查看进度、日志与成片。
8. 到“成片投稿”预览、本地审核和检查参数。
9. 确定要投稿时再开启权限、确认提交，并同步平台状态。

## 十一、当前边界

- 插件提供方案驱动的创作流程，不提供专业剪辑软件那样的自由时间线编辑。
- 不保证每条视频都有字幕、可下载原片或可用原声。
- 不保证模型生成内容的准确性、笑点和最终审美，仍需人工查看。
- 不保证 B站投稿通过或绕过平台风控。
- 主要在 Windows + DSH web 环境维护验证，其他系统和全新设备完整流程仍需验证。
- 渲染和素材下载会使用本地算力、磁盘及网络；模型调用可能产生所选服务的费用。

这是一套“采集—整理—生成方案—渲染—人工审核—投稿”的创作辅助工作台，最终发布决定保留给使用者。
